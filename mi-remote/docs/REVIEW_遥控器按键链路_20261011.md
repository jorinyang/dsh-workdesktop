## 一、按键生效机制（完整链路）

一次物理按压要变成 DSH 里的一个动作，经过五段。每段都有本文档的实测证据。

| 段 | 做什么 | 实现位置 | 本次状态 |
| --- | --- | --- | --- |
| 1 | 遥控器发 BLE HID 报告 | 系统蓝牙栈 | 正常 |
| 2 | 采集器在 `WUDFHost.exe` 里 hook `NtDeviceIoControlFile`，把 HID 报告里的 usage 列表写进 `state/keys.jsonl` | `engine/rc003-tap.py` | 正常 |
| 3 | 引擎每 6ms 轮询该文件，按 `click` / `double` / `hold` 三档判定 | `engine/read-engine.py` | 正常 |
| 4 | 判定结果通过 `SendInput` 注入按键（同时给 `wVk` 和 `wScan`） | 同上 | 正常 |
| 5 | DSH 按 `event.code` 匹配快捷键，执行命令 | `packages/client/shortcuts` | 正常 |

### 第 4 段的两个关键约束

**约束一：必须同时给扫描码。** DSH 的快捷键按 `event.code`（物理键位）匹配（`packages/client/shortcuts/src/binding.ts`），只给 `wVk` 时 Chromium 推不出 `event.code`、显示为空，DSH 永远匹配不上。两个引擎实现和 `engine/inject.py` 都已设置 `wScan`。

**约束二：注入进程的完整性级别不能低于目标窗口。** UIPI 规定低完整性进程无法向高完整性窗口注入，而 `SendInput` 仍返回成功（静默失败）。360 的 `360Box64` / `360AntiHijack` 驱动会把未签名程序压到 Low（4096），而 `python.exe` 保持 High（12288）。插件因此会自动探测并优先选 python 版引擎（`probeEngineIntegrity` / `pickEngine`）。

### 第 3 段的三档判定

- **单击**：松手即执行；只有该键配了双击动作时才等 `DOUBLE_MS`（320ms）
- **双击**：`DOUBLE_MS` 内两次松手
- **长按**：按住超过 `HOLD_MS`（650ms）

鼠标移动类动作在按住期间循环注入，松手时由 `move-stop` 停止。

## 三、发现的问题

### 已修（本次）

**P1 · 日志没有时间戳，导致无法区分新旧记录。**
`key` 和 `fire` 两类记录原来都不带时间，日志又是 append-only（本次已涨到 22000+ 行），
于是"最后几条 `Backspace` 是改配置之前的旧记录，还是现在还在发"根本判不出来 —— 排查时在这上面卡住过。
**修**：`read-engine.py` 的 `emit()` 统一补 `ts`（墙钟毫秒），所有调用点自动生效。已实测 85/85 行带 `ts`。

**P2 · 客户端插件缺 `shortcuts` 声明会整个加载失败。**
`ctx.shortcuts` 是经 ctx 代理的服务读取，不在 `inject` 里会抛
`cannot get property "shortcuts" without inject`，客户端条目进 failed、面板都不显示。
**修**：`inject: ['slots', 'timer', 'shortcuts']`。

**P3 · 用错了搜索框的提示文字，导致读不到关键字。**
原实现匹配「筛选」和拉丁 `filter`/`search`，而 DSH 的实际值是**「搜索会话名称」**
（`ui-workspace/src/client/locales.ts:40`），两个都不匹配 → 永远返回空串。
**修**：按完整 placeholder 精确认（中英），再留一组宽松词兜底。

**P4 · 搜索结果的键盘导航 DSH 本身没有。**
结果树有 `role="tree"` / `role="treeitem"`，但一行 ↑/↓/Enter 处理都没有。
**修**：插件侧接管（capture 阶段），搜索框有内容时生效；焦点在聊天框、或带修饰键时一律不接管。

**P5 · 同一个会话被反复重开。**
打开动作原来不管当前在哪都点一下，连按就看起来像"反复切到同一条"。
**修**：三处都加了"已经是当前会话就什么都不做"（判据用 DSH 挂在选中行上的 `aria-selected`）。

### 未修（需要用户决定）

**P6 · `back` 单击 = `Backspace`。**
在浏览器里、焦点不在输入框时，`Backspace` 等于**后退**。连按就是"页面一直在刷新"。
**建议换 `Delete`**：同样能删字，不触发后退。
**现状**：我改成 `Delete` 之后，用户在面板里保存时又被覆盖回 `Backspace`（见 §四）。

**P7 · `home` 单击 = `Ctrl+Alt+K`。**
那是 DSH 的「搜索会话」。**所以每按一次主页，搜索框就弹一次** —— 用户报的"时不时跳出搜索框"就是这个。
**这不是故障，是绑定的语义。** 要改的是绑定，不是插件。

**P8 · `MouseLeft` / `MouseRight` 类绑定（本次已由用户改掉）。**
它们是**在光标位置真的点鼠标**：光标停在左侧栏会话列表上，点一下就是切换会话；右键还会弹菜单。
用户报的"反复切换会话"就是这个。现已改为 `Ctrl+Alt+1` / `Ctrl+Alt+4`。

### 机制的固有限制（不是 bug，但要知道）

**L1 · 注入进程必须不低于目标窗口的完整性级别**（见 §一 约束二）。
360 驱动在内存里时插件自动用 python 引擎；重启后驱动消失，C# 引擎会接手。

**L2 · 新引擎实现必须加进清杀名单。**
Windows 不会在父进程死亡时连带杀死子进程。`killStrayPipeline` 的名单漏过一次
`read-engine.py`，结果攒了 4 个引擎实例、每个动作执行多遍、音量触发两次。
`/bridge/auto` 现在每次开头都无条件清干净。

**L3 · 采集器/引擎绝不能用 `stdio: 'ignore'`。**
曾经因此把"采集器启动即崩"（`ValueError: invalid literal for int(): '--sayall-owns-voice'`）藏了很久。
现在输出统一进 `state/collector.log` / `state/engine.log`。

## 四、流程上的一条教训（关于我）

**我不该直接改用户的 `mapping.json`。**
本次我把 `back` 改成 `Delete`、给 `menu`/`tv` 换了绑定，是通过脚本直接写文件的。
用户随后在插件面板里保存，面板用它加载时的旧状态整份覆盖，我的改动全被冲掉
（现在盘上 `back` 又是 `Backspace`，`home` 的双击还空了）。

**正确做法**：把建议给用户，由他在面板里改；或改完之后明确告知"面板里再保存会覆盖"。
