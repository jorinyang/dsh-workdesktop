release: 0.10.1 - live group refit, collapse, and edge re-anchoring

Dragging a member now resizes the group box continuously, in both directions, and the
box always holds the members. Two separate causes were behind the earlier lag. The host
computed the refit from the stage as it was before the move, so it was always one step
behind - it grew on the second drag and could leave a member outside on the way back.
And the gesture's mousemove was only bound to the canvas element, so dragging past the
canvas edge stopped the events and the element froze; the handler is now also bound to
the window for the duration of a gesture.

Dragging the group box now moves its members during the drag rather than after release.
The offset lookup was keyed on the selection, and dragging a group selects only the
group, so the members never received an offset. It is keyed on the set being dragged
now. That fix exposed a double count: the box was recomputed from the members' live
positions and then had the group's own offset added on top, so it travelled twice as
far as the pointer. Both are correct now: drag 120, members move 120, box moves 120.

Collapse follows upstream Section.tsx. The box shrinks to the title bar, matching the
collisionBox getter, and widths never fall below the title width (line 171). Edges are
re-anchored for drawing only: edges between two members of the same collapsed group are
not drawn, and edges from a member to something outside are drawn from the collapsed box
instead. The stored endpoints are never touched, so expanding restores the original
member-to-outside edges with nothing to undo.

Also fixes the panel's copy offsets and re-anchors edge geometry to the collapsed box
rather than the stored one, which is what made re-anchored edges still appear to start
at the old outline.

Verified: host 19/0, client 43/0, seat contract 20/0, document layer 25/0, groups 19/0,
live refit 12/0 in a real browser, collapse and edge re-anchoring 8/0, search and
multi-select 18/0.
